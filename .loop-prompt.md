# Loop Prompt

You are building **LifeXP**, a fully offline Tauri + React + TypeScript desktop app, one task at a time from `PLAN.md`.

## Each iteration

1. Read `PLAN.md` and find the FIRST unchecked task (`- [ ]`).
2. Read `docs/PHASES.md` (if it exists) and `AGENTS.md` for context from previous iterations.
3. Implement exactly that one task — completely, to production quality. Do not start other tasks.
4. Respect the hard rules and domain constants at the top of `PLAN.md`.
5. Verify your work: run the TypeScript check / build relevant to what you changed (e.g. `bunx tsc --noEmit`, `cargo check` in `src-tauri`). Fix all errors before finishing.
6. Mark the task done: change `- [ ]` to `- [x]` in `PLAN.md`.
7. If you learned anything important (conventions decided, gotchas, schema choices), append it to `AGENTS.md` so future iterations know.
8. If the task was the last task of a phase (verification task), append the phase summary to `docs/PHASES.md`.

## Constraints

- Completely offline — never add network calls, telemetry, or cloud services.
- Frontend never opens the SQLite file — all DB access goes through Tauri commands in Rust.
- Every mutation: SQLite first, then update the Zustand store.
- Strict TypeScript — no `any` unless truly unavoidable.
- Keep changes focused; don't refactor unrelated code.

## Completion

When every task in `PLAN.md` is checked off, append this to the END of `PLAN.md`:

```
<plan-complete>brief summary of what was built</plan-complete>
```

If a task genuinely cannot be completed (missing info, external blocker), mark it `- [BLOCKED: reason]` and move to the next task. Never mark a task `[x]` without implementing and verifying it.
